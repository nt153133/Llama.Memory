## 2024-05-24 - [Optimize GetFrequencyTables]
**Learning:** `GetFrequencyTables` in `PatternSearcher.cs` builds byte and pair frequency tables on the first Search. The original approach iterated through the data span twice (once for bytes, once for pairs) causing unnecessary memory reads. Even worse, the array bound checks weren't elided.
**Action:** Used `MemoryMarshal.GetReference`, `MemoryMarshal.GetArrayDataReference`, and `Unsafe.Add` to create a fast path that populates both the byte frequency and pair frequency arrays in a single, bounds-check-free pass. Combining the passes and bypassing bounds checks reduced the time from 5.5s down to 1.9s for a 100MB array (over 10 iterations) and 565ms to 191ms for a single iteration.

## 2023-10-27 - [Optimize PatternSearcher Match functions]
**Learning:** In C#, explicit loop unrolling for memory matching using `Unsafe.ReadUnaligned<uint>` and `Unsafe.ReadUnaligned<ushort>` is significantly faster than using single-byte `for` loops. While hardware intrinsics like `Vector128` or `Vector256` are often used for such optimizations, they were actually slightly slower for short patterns due to overhead and potentially setup costs in this specific `MatchAt` and `Match` logic where the patterns may be relatively small but numerous.
**Action:** Unrolled the byte loops into reading 4-byte and 2-byte chunks instead, which reduced `SearchManyPatterns` execution time from ~240ms down to ~180ms for small patterns and drastically cut matching overhead for larger arrays without the need for complex vector registers setup.
