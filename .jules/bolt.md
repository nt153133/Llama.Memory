## 2024-05-24 - [Optimize GetFrequencyTables]
**Learning:** `GetFrequencyTables` in `PatternSearcher.cs` builds byte and pair frequency tables on the first Search. The original approach iterated through the data span twice (once for bytes, once for pairs) causing unnecessary memory reads. Even worse, the array bound checks weren't elided.
**Action:** Used `MemoryMarshal.GetReference`, `MemoryMarshal.GetArrayDataReference`, and `Unsafe.Add` to create a fast path that populates both the byte frequency and pair frequency arrays in a single, bounds-check-free pass. Combining the passes and bypassing bounds checks reduced the time from 5.5s down to 1.9s for a 100MB array (over 10 iterations) and 565ms to 191ms for a single iteration.
## 2024-05-26 - [Optimize PrefixReject Short Pattern Fast Path]
**Learning:** `PrefixReject` in `PatternSearcher.cs` fell back to a slow byte-by-byte loop for short prefixes (`prefLen < 8`). This resulted in noticeable overhead for short search patterns since `PrefixReject` runs on every potential hit location.
**Action:** Implemented a fast path that attempts to read an entire `ulong` directly using `Unsafe.ReadUnaligned`, provided there are at least 8 bytes left in the buffer to prevent out of bounds memory reads. Since `cp.PrefixMask` correctly isolates only the first `prefLen` bytes, any extra bytes read are harmlessly masked out. This replaced a multi-instruction loop with a single unaligned memory read for the vast majority of search positions. Resulted in a ~22% reduction in search time for short patterns (measured dropping from 753ms to 586ms for 100 search iterations on 10MB data).
